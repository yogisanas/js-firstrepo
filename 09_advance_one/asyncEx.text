11. What is async in JavaScript?
      The async keyword makes a function return a Promise.

      async function greet() {
          return "Hello";
      }
      greet().then(console.log);

      Output: Hello
      
      Even though we return a string, the async function wraps it in a fulfilled Promise.


12. What is await?
      await pauses the execution of the surrounding async function until a Promise settles. 
           It returns the fulfillment value or throws the rejection reason.

      async function getData() {
          const result = await Promise.resolve("Data received");
          console.log(result);
      }
      
      getData();
      
      Output: Data received


13. What is the difference between Promise and Async/Await?
           Promise	                                           Async/Await
      Uses .then() and .catch().	                Uses await and commonly try...catch.
      Can involve chained callbacks.	            Often makes asynchronous code easier to read.
      Directly represents an asynchronous result.	Provides syntax for working with Promises.

      Both work with Promises; async/await is not a replacement for the Promise mechanism itself.


14. How do you handle errors in Async/Await?
      Use try...catch.

      async function getData() {
          try {
              const result = await Promise.reject("Something went wrong");
              console.log(result);
          } catch (error) {
              console.log(error);
          }
      }
      
      getData();
      
      Output: Something went wrong


15. Can we use await without async?
      In a regular JavaScript function, generally no. You can use await inside an async function, 
         or at the top level of supported JavaScript modules.


16. Does async/await block the entire JavaScript program?
      No. await pauses the surrounding async function, not the entire JavaScript program. 
           Other code can continue executing.
      async function test() {
          console.log("A");
      
          await Promise.resolve();
      
          console.log("B");
      }
      
      test();
      console.log("C");
      
      Output:-
      A
      C
      B


17. What is the difference between sequential and parallel execution with Async/Await?
      Sequential: Each operation waits for the previous one.
      const a = await getData1();
      const b = await getData2();
      
      Parallel: Start both operations before awaiting their combined results.
      const [a, b] = await Promise.all([
          getData1(),
          getData2()
      ]);
      
      Parallel execution can be faster when the operations are independent.


18. What happens if an awaited Promise rejects?
      The await expression throws the rejection reason. You can handle it using try...catch.


19. Why do we use Async/Await with fetch()?
      fetch() returns a Promise. Async/await lets us write code that waits for the response 
           before processing it.
      async function getUsers() {
          try {
              const response = await fetch(
                  "https://jsonplaceholder.typicode.com/users"
              );
      
              if (!response.ok) {
                  throw new Error("HTTP error: " + response.status);
              }
      
              const data = await response.json();
              console.log(data);
          } catch (error) {
              console.log(error.message);
          }
      }
      
      getUsers();
      
      Remember: fetch() generally does not reject for HTTP errors such as 404 or 500, 
         so checking response.ok is important.


20. What is the output of this code?
       This is a common interview question.

       console.log("Start");
       
       setTimeout(() => {
           console.log("Timeout");
       }, 0);
       
       Promise.resolve().then(() => {
           console.log("Promise");
       });
       
       console.log("End");
       
       Output:-
       Start
       End
       Promise
       Timeout
       
       Why?
       1. Synchronous code executes first: Start, then End.
       2. Promise callbacks run as microtasks.
       3. The setTimeout callback runs later as a task (often called a macrotask).
